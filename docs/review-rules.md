## Code Review Rules

1. **Quitting or restarting the desktop app never leaves transfer processes running.** A killed server runs no cleanup, so its adb and copy children keep running and leave partial files behind. A change that adds or alters a way to end the server process asks the server to force-stop its transfers before killing it, unless the server has already reported a clean shutdown; killing a server that then never exits is allowed. The processes to stop come from the server's own record of what it started, never from scanning or matching system processes, which is how the adb daemon other tools share gets killed. A new way to quit or restart joins the one shared shutdown instead of exiting because another path started it. The app exits within 10 seconds of the quit going ahead (the user confirming, or no confirmation being needed); the bounded wait for the active-job count that comes first is not part of the 10. Breaking this is at least P1.

2. **The API token and the pairing secret (the QR password or a code the user typed) never reach a log file, a failure page or dialog, or the desktop app's stdout and stderr.** Three hand-offs are by design and are not leaks: the token link browser mode and dev mode print to their terminal, the token fragment the desktop app loads into its own window, and the pairing QR code. Relayed stream output must stay redacted when a chunk boundary splits the value: redacting whole lines is the safe path, and per-chunk redaction lets a split value through. A change that can leak either value, even on an unlucky chunk boundary, is at least P1. The leak needs a path in this app's code that writes, relays or shows the value; text inside an error that Electron or Node creates and handles itself is not such a path unless this code prints or shows it.
